# 专业研究报告技能

## 概述

本技能以 Markdown 格式生成专业、咨询级的研究报告，涵盖 **市场分析、消费者洞察、品牌策略、财务分析、行业研究、竞争情报、投资研究和宏观经济分析**等领域。它分两个不同的阶段运作：

1. **第一阶段 — 分析框架生成**：给定研究主题，制作包含章节骨架、每章数据要求、分析逻辑和可视化计划的严格分析框架。
2. **第二阶段 — 报告生成**：在其他技能收集数据后，将所有输入综合成最终完善的报告。

输出遵循麦肯锡/BCG 咨询风格。报告语言遵循 `output_locale` 设置（默认：`zh_CN` 中文）。

## 数据真实性协议

**严格遵守规则**：报告中呈现的所有数据和图表中可视化的所有数据必须直接来自提供的 **数据摘要** 或 **外部搜索发现**。
- **禁止虚构**：不要编造、估计或模拟数据。如果数据缺失，说明"数据不可用"而非捏造数字。
- **可追溯来源**：每个主要声明和图表必须可追溯到输入数据包。

## 核心能力

- **从头设计分析框架**，只需给定研究主题和范围
- 将原始数据转换为结构化、高深度的研究报告
- 遵循每个子章节的 **"视觉锚点 → 数据对比 → 综合分析"** 流程
- 按照 **"数据 → 用户心理 → 战略含义"** 链条产生洞察
- 嵌入预生成的图表并构建对比表
- 生成符合 **GB/T 7714-2015** 标准的内联引用
- 以 `output_locale` 指定的语言输出报告，保持专业咨询语气
- 适应领域（营销、金融、行业等）的分析深度和结构

## 何时使用此技能

**始终加载此技能当：**

- 用户请求市场分析、消费者洞察报告、财务分析、行业研究或任何咨询级分析报告
- 用户提供研究主题，需要在数据收集之前建立结构化分析框架
- 用户提供数据摘要、分析框架或图表文件以综合成报告
- 用户需要专业咨询风格的研究报告
- 任务涉及将研究发现转化为结构化战略叙述

# 第一阶段：分析框架生成

## 目的

给定**研究主题**（例如"Z世代护肤市场分析"、"新能源汽车行业竞争格局"、"品牌X消费者画像"），生成完整的**分析框架**，作为下游数据收集和最终报告生成的蓝图。

## 第一阶段输入

| 输入 | 描述 | 必填 |
|-------|-------------|----------|
| **研究主题** | 要分析的主题或问题 | 是 |
| **范围/约束** | 地理范围、时间范围、行业细分、目标受众等 | 可选 |
| **特定角度** | 用户想要探索的任何特定角度或假设 | 可选 |
| **领域** | 分析领域：市场、金融、行业、品牌、消费者、投资等 | 推断 |

## 第一阶段工作流程

### 步骤 1.1：理解研究主题

- 解析研究主题以识别**核心实体**（市场、品牌、产品、行业、消费者细分、金融工具等）
- 识别**分析领域**（营销、金融、行业、竞争、消费者、投资、宏观等）
- 根据领域确定**自然分析维度**：

| 领域 | 典型维度 |
|--------------------|--------------------------------------------------|
| 市场分析 | 市场规模、增长趋势、市场细分、增长驱动因素、竞争格局、消费者画像 |
| 品牌分析 | 品牌定位、市场份额、消费者感知、营销策略、竞争对手比较 |
| 消费者洞察 | 人口统计画像、购买行为、决策旅程、痛点、场景分析 |
| 财务分析 | 宏观环境、行业趋势、公司基本面、财务指标、估值、风险评估 |
| 行业研究 | 价值链分析、市场规模、竞争格局、政策环境、技术趋势、进入壁垒 |
| 投资尽职调查 | 商业模式、财务健康、管理评估、市场机会、风险因素、退出路径 |
| 竞争情报 | 竞争对手识别、战略比较、SWOT分析、差异化定位、市场动态 |

### 步骤 1.2：选择分析框架和模型

根据已识别的领域和研究主题，选择**一个或多个**专业分析框架来构建每个章节的推理结构。选定的框架指导章节骨架（步骤 1.3）中的**分析逻辑**。

#### 战略与环境分析

| 框架 | 描述 | 最佳用途 |
|-----------|-------------|----------|
| **SWOT 分析** | 优势、劣势、机会、威胁 | 品牌评估、竞争定位、战略规划 |
| **PEST / PESTEL 分析** | 政治、经济、社会、技术（+ 环境、法律） | 宏观环境扫描、市场进入评估、政策影响分析 |
| **波特五力** | 供应商议价能力、买方议价能力、新进入者威胁、替代品威胁、行业竞争 | 行业竞争格局、进入壁垒评估、利润率分析 |
| **波特钻石模型** | 要素条件、需求条件、相关产业、企业战略与结构 | 国家/地区竞争优势分析 |
| **VRIO 分析** | 价值、稀缺性、模仿性、组织 | 核心竞争力评估、资源优势分析 |

#### 市场与增长分析

| 框架 | 描述 | 最佳用途 |
|-----------|-------------|----------|
| **STP 分析** | 细分、目标、定位 | 市场细分、目标市场选择、品牌定位 |
| **BCG 矩阵（增长-份额矩阵）** | 明星、金牛、问题、瘦狗 | 产品组合管理、资源配置决策 |
| **安索夫矩阵** | 市场渗透、市场开发、产品开发、多元化 | 增长战略选择 |
| **产品生命周期（PLC）** | 引入、成长、成熟、衰退 | 产品策略制定、市场时机决策 |
| **TAM-SAM-SOM** | 总市场/可服务市场/可获得市场 | 市场规模、机会量化 |
| **技术采用生命周期** | 创新者 → 早期采用者 → 早期大众 → 晚期大众 → 落后者 | 新兴技术/类别渗透分析 |

#### 消费者与行为分析

| 框架 | 描述 | 最佳用途 |
|-----------|-------------|----------|
| **消费者决策旅程** | 认知 → 考虑 → 评估 → 购买 → 忠诚 | 消费者行为路径映射、触点优化 |
| **AARRR 漏斗（海盗指标）** | 获取、激活、留存、收入、推荐 | 用户增长分析、转化率优化 |
| **RFM 模型** | 最近一次消费、消费频率、消费金额 | 客户价值细分、精准营销 |
| **马斯洛需求层次** | 生理 → 安全 → 社交 → 尊重 → 自我实现 | 消费者心理学分析、产品价值主张 |
| **待完成工作（JTBD）** | 用户在特定背景下需要完成的"工作" | 需求洞察、产品创新方向 |

#### 财务与估值分析

| 框架 | 描述 | 最佳用途 |
|-----------|-------------|----------|
| **杜邦分析** | ROE = 净利润率 × 资产周转率 × 权益乘数 | 盈利能力分解、财务健康诊断 |
| **DCF（折现现金流）** | 自由现金流折现 | 企业/项目估值 |
| **可比公司分析** | 市盈率、市净率、市销率、企业价值/EBITDA 倍数比较 | 相对估值、同行基准 |
| **EVA（经济增加值）** | 税后营业利润 - 资本成本 | 价值创造能力评估 |

#### 竞争与战略定位

| 框架 | 描述 | 最佳用途 |
|-----------|-------------|----------|
| **基准化** | 关键绩效指标逐项比较 | 竞争对手差距分析、最佳实践识别 |
| **战略群体映射** | 沿两个关键维度聚类竞争对手 | 竞争格局可视化、空白区识别 |
| **价值链分析** | 主要活动 + 支持活动的价值分解 | 成本优势来源、差异化机会识别 |
| **蓝海战略** | 价值曲线、四项行动框架（消除-减少-提升-创造） | 差异化创新、新市场空间创造 |
| **感知映射** | 沿两个消费者感知维度绘制品牌位置 | 品牌定位分析、市场空白发现 |

#### 行业与供应链分析

| 框架 | 描述 | 最佳用途 |
|-----------|-------------|----------|
| **行业价值链** | 上游 → 中游 → 下游分解 | 行业结构理解、利润分布分析 |
| **Gartner 炒作周期** | 技术触发 → 期望峰值 → 幻灭低谷 → 启蒙斜坡 → 生产力 plateau | 新兴技术成熟度评估 |
| **GE-麦肯锡矩阵** | 行业吸引力 × 竞争实力 | 业务组合优先级、投资决策 |

#### 选择原则

1. **领域优先**：根据步骤 1.1 识别的领域，从上述工具包中选择 **2-4** 个最相关的框架
2. **互补性**：选择互补而非重叠的框架（例如宏观层面 PESTEL + 微观层面波特五力）
3. **深度优于广度**：深入应用2个框架优于表面堆叠6个
4. **数据可行性**：选定的框架必须可由下游数据收集技能支持 — 如果框架所需的数据无法合理获得，降级或替换
5. **明确映射**：在章节骨架中，明确标注每个章节使用哪个框架及其应用方式

#### 框架选择输出格式

```markdown
## 框架选择

| 章节 | 选定的框架 | 应用 |
|---------|----------------------|-------------|
| 市场规模与增长趋势 | TAM-SAM-SOM + 产品生命周期 | TAM-SAM-SOM 量化市场空间，PLC 确定市场阶段 |
| 竞争格局评估 | 波特五力 + 战略群体映射 | 五力评估行业竞争强度，群体映射可视化竞争定位 |
| 消费者画像 | RFM + 消费者决策旅程 | RFM 细分客户价值，决策旅程识别关键转化节点 |
| 品牌策略建议 | SWOT + 蓝海战略 | SWOT 总结整体格局，蓝海指导差异化方向 |
```

### 步骤 1.3：设计章节骨架

生成层次化章节结构。每个章节必须包含：

1. **章节标题** — 专业、简洁、基于主题（遵循格式部分的标题约束）
2. **分析目标** — 本章旨在揭示什么
3. **分析逻辑** — 推理链或框架（必须引用步骤 1.2 中选定的框架）
4. **核心假设** — 待数据验证或反驳的初步假设

#### 章节骨架输出格式

```markdown
## 分析框架

### 第1章：[标题]
- **分析目标**：[本章旨在...]
- **分析逻辑**：[使用的框架或推理链]
- **核心假设**：[待验证的假设]
- **数据要求**：（见步骤 1.4）
- **可视化计划**：（见步骤 1.5）

### 第2章：[标题]
...
```

### 步骤 1.4：定义每章数据查询要求

对于每个章节，具体指定**需要收集的确切数据**。这是通往下游数据收集技能的桥梁。

每个数据要求条目必须包含：

| 字段 | 描述 |
|-------|-------------|
| **数据指标** | 所需的具体指标或数据点（例如"中国护肤品市场规模 2020-2025（单位：十亿元人民币）"）|
| **数据类型** | 定量、定性或混合 |
| **建议来源** | 建议的来源类别：行业报告、财务报表、政府统计、社交媒体、电商平台、调查数据、新闻 |
| **搜索关键词** | 数据收集代理的建议搜索查询 |
| **优先级** | P0（必需）/ P1（重要）/ P2（补充）|
| **时间范围** | 数据应涵盖的时间段 |

#### 数据要求输出格式（每章）

```markdown
#### 数据要求

| # | 数据指标 | 数据类型 | 建议来源 | 搜索关键词 | 优先级 | 时间范围 |
|---|-------------|-----------|-------------------|-----------------|----------|------------|
| 1 | 市场规模（十亿元人民币） | 定量 | 行业报告、政府统计 | "中国护肤品市场规模 2024" | P0 | 2020-2025 |
| 2 | 复合年增长率 | 定量 | 行业报告 | "护肤品复合年增长率" | P0 | 2020-2025 |
| 3 | 子品类份额 | 定量 | 电商平台、行业报告 | "护肤品品类份额 乳霜 精华 防晒" | P1 | 最新 |
| 4 | 政策与法规更新 | 定性 | 政府公告、新闻 | "化妆品法规 2024" | P2 | 过去1年 |
```

### 步骤 1.5：定义每章可视化和内容结构

对于每个章节，指定**计划的可视化**和最终报告的**内容结构**：

| 字段 | 描述 |
|-------|-------------|
| **可视化类型** | 图表类型：折线图、柱状图、饼图、散点图、雷达图、热力图、桑基图、对比表等 |
| **可视化标题** | 图表的描述性标题 |
| **可视化数据映射** | 哪些数据指标映射到 X/Y 轴或分段 |
| **对比表设计** | 列标题和对比维度 |
| **论点结构** | 计划的"是什么 → 为什么 → 所以怎样"叙述大纲 |

#### 可视化计划输出格式（每章）

```markdown
#### 可视化与内容计划

**图表 1**：[类型] — [标题]
- X轴：[维度]，Y轴：[指标]
- 数据来源：对应数据要求 #1、#2

**对比表**：
| 维度 | 项目A | 项目B | 项目C |
|-----------|--------|--------|--------|

**论点结构**：
1. **观察（是什么）**：[数据揭示的表面现象]
2. **归因（为什么）**：[驱动因素或根本原因]
3. **含义（所以怎样）**：[战略含义或建议行动]
```

# 第一阶段→第二阶段交接：数据收集与图表生成

分析框架生成后，交给**其他数据收集技能**（例如 deep-research、data-analysis、网络搜索代理）：

1. 执行每个章节数据要求中的**搜索关键词**
2. 收集定量数据、定性洞察和来源 URL
3. 根据**可视化和内容计划**生成图表
4. 返回包含以下内容的**数据包**：
   - **数据摘要**：按章节组织的原始数字、指标和定性发现
   - **图表文件**：生成的图表图像及其本地文件路径
   - **外部搜索发现**：用于引用的 URL 和摘要

> **此技能不执行数据收集。** 它只生成框架（第一阶段）和最终报告（第二阶段）。
>
> **图表生成**：如果有可视化/图表技能可用（例如 data-analysis、image-generation），图表生成可以推迟到第二阶段开始 — 见步骤 2.3。

# 第二阶段：报告生成

## 目的

接收上游的完成的**分析框架**和**数据包**，将其综合成最终咨询级报告。

## 第二阶段输入

| 输入 | 描述 | 必填 |
|-------|-------------|----------|
| **分析框架** | 第一阶段生成的分析框架文档 | 是 |
| **数据摘要** | 数据收集阶段按章节组织的数据 | 是 |
| **图表文件** | 生成的图表图像的本地文件路径。如果未提供，将在步骤 2.3 使用可用可视化技能生成 | 可选 |
| **外部搜索发现** | 用于内联引用的 URL 和摘要 | 可选 |

## 第二阶段工作流程

### 步骤 2.1：接收并验证输入

验证所有必填输入都存在：

1. **分析框架** — 确认包含章节骨架、数据要求和可视化计划
2. **数据摘要** — 确认包含按章节组织的数据，对照 P0 要求交叉验证
3. **图表文件** — 确认文件路径是有效的本地路径

如果任何 P0 数据缺失，在报告中注明并标记给用户。

### 步骤 2.2：映射报告结构

从分析框架映射最终报告结构：

1. **摘要** — 带关键要点的执行摘要
2. **引言** — 背景、目标、方法论
3. **主体章节（2...N）** — 从框架章节骨架映射
4. **结论** — 纯、客观的综合
5. **参考文献** — 按 GB/T 7714-2015 格式的参考文献

### 步骤 2.3：生成章节图表（报告前可视化）

在撰写报告之前，根据分析框架的**可视化和内容计划**生成所有计划的图表。此步骤确保每个子章节在叙事写作开始前都准备好其"视觉锚点"。

#### 何时执行此步骤

- **图表文件已提供**：跳过此步骤 — 直接进入步骤 2.4。
- **图表文件未提供但有可视化技能可用**：执行此步骤先生成所有图表。
- **没有图表文件且无可视化技能**：跳过此步骤 — 在步骤 2.4 中使用对比表作为主要视觉锚点，并注明缺少图表。

#### 图表生成工作流程

1. **提取图表任务**：解析分析框架中的所有`可视化和内容计划`条目，构建图表生成任务清单：

| # | 章节 | 图表类型 | 图表标题 | 数据映射 | 数据来源 |
|---|---------|------------|-------------|--------------|-------------|
| 1 | 2.1 | 折线图 | 市场规模趋势 2020-2025 | X：年份，Y：市场规模（十亿元人民币） | 数据要求 #1、#2 |
| 2 | 3.1 | 饼图 | 消费者年龄分布 | 分段：年龄组，值：份额% | 数据要求 #5 |
| ... | ... | ... | ... | ... | ... |

2. **准备图表数据**：对于每个图表任务，从**数据摘要**中提取相应的数据点。
   > **关键**：只使用数据摘要中提供的数字。不要编造或"平滑"数据以使图表看起来更好。如果数据点缺失，图表必须反映这一现实（例如断线或缺失条），或者必须调整图表类型。

3. **委托给可视化技能**：为每个图表任务调用可用的可视化/图表技能：
   - 图表类型和标题
   - 结构化数据
   - 轴标签和格式偏好
   - 输出文件路径约定：`charts/chapter_{N}_{chart_index}.png`

4. **收集图表文件路径**：记录所有生成的图表文件路径以便在步骤 2.4 嵌入：

```markdown
## 生成的图表
| # | 章节 | 图表标题 | 文件路径 |
|---|---------|-------------|-----------|
| 1 | 2.1 | 市场规模趋势 2020-2025 | charts/chapter_2_1.png |
| 2 | 3.1 | 消费者年龄分布 | charts/chapter_3_1.png |
```

5. **验证**：确认所有 P0 优先级图表都已生成。如果任何图表生成失败，注明并在子章节中回退到对比表。

> **原则**：在开始报告写作之前完成所有图表生成。这确保了一致的视觉叙事，避免了生成与写作的交织。

### 步骤 2.4：撰写报告

对于每个子章节，遵循**"视觉锚点 → 数据对比 → 综合分析"**流程：

1. **视觉证据块**：使用 `![图片描述](实际文件路径)` 嵌入图表 — 使用步骤 2.3 收集的文件路径
2. **数据对比表**：为关键指标创建 Markdown 对比表
   > **来源规则**：表中的每个数字必须来自数据摘要。禁止虚构。
3. **综合叙事分析**：按照"是什么 → 为什么 → 所以怎样"撰写分析文本
   > **叙事规则**：叙事必须解释*提供的*数据。不要做出没有输入支持的声明。

每个子章节必须以 robust 分析段落结束（至少 200 字）：
- 综合冲突或强化的数据点
- 揭示底层用户张力或机会
- 可选地以 blockquote（`>`）中的 punchy "一句话真相" 结束

### 步骤 2.5：最终结构自检

输出前，确认报告包含**所有顺序正确的章节**：

```
摘要 → 1. 引言 → 2...N. 主体章节 → N+1. 结论 → N+2. 参考文献
```

另外验证：
- 步骤 2.3 生成的所有图表都嵌入在正确的子章节中
- `![](路径)` 引用中的图表文件路径有效
- 没有图表的子章节有对比表作为视觉锚点

报告**不得在结论后停止** — 必须包含参考文献作为最终章节。

## 格式与语气标准

### 咨询语气

- **语气**：麦肯锡/BCG — 权威、客观、专业
- **语言**：所有标题和内容使用 `output_locale` 指定的语言
- **数字格式**：使用英语逗号作为千位分隔符（`1,000` 而非 `1，000`）
- **数据强调**：**粗体**重要观点和关键数字

### 标题约束

- **编号**：使用直接后跟标题的标准编号（`1.`、`1.1`）
- **禁止前缀**：不要使用"章节"、"部分"、"节"作为前缀
- **允许的语气词**：分析、画像、概述、洞察、评估
- **禁止的词**："解码"、"DNA"、"秘密"、"心灵图景"、"太阳系"、"解锁"

### 子章节结论

- **要求**：每个子章节以 robust 分析段落结束（至少 200 字）。
- **叙事流**：此段落必须看起来像文本的自然延续。它必须将章节发现综合成战略判断。
- **内容逻辑**：
    1. 综合上面冲突或强化的数据点。
    2. 揭示*底层*用户张力或机会。
    3. 关键洞察：**可选**：如果你有一个简洁、punchy 的"一句话真相"，用它作为**Blockquote**（`>`）放在最末尾以锚定章节。

### 洞察深度（"所以怎样"链条）

每个洞察必须连接**数据 → 用户心理 → 战略含义**：

```
❌ 不好："女性占60%。策略：针对女性。"

✅ 好的："女性占60%，TGI高达180。**这表明**
   购买决策由审美和社会认同驱动，而非纯实用性。**因此**
   媒体支出应转向视觉重的平台（例如小红书/Instagram）以最大化点击率，
   仅将男性受众作为次要的礼品购买细分。"
```

### 参考文献

- **内联**：使用 markdown 链接表示来源（例如使用外部搜索发现时 `[来源标题](URL)`）
- **参考文献部分**：严格按 **GB/T 7714-2015** 格式化

### Markdown 规则

- **立即开始**：直接以 `# 报告标题` 开始 — 无介绍性文字
- **无分隔符**：不要使用水平线（`---`）

## 注意事项

- 此技能在多步骤代理工作流的**两个阶段**运作：
  - **第一阶段**产生分析框架和数据收集要求
  - **数据收集**由其他技能执行（deep-research、data-analysis 等）
  - **第二阶段**接收收集的数据并产生最终报告
- 动态标题：**将**框架中的主题重写为专业、简洁、基于主题的标题
- 结论部分必须**不包含**详细建议 — 那些属于前面的主体章节
- **零虚构政策**：报告中的每个声明、图表和数字必须得到输入数据摘要中数据点的支持。如果数据缺失，承认它。
- **可追溯性**：如果请求，你必须能够指向支持声明的数据摘要或外部搜索发现中的具体行。
- 框架应调整其分析维度和深度以适应特定领域（财务分析使用的框架不同于消费者洞察）
- 当研究主题不明确时，默认为最广泛合理的范围并注明假设
