# 新闻通讯生成技能

## 概述

本技能生成专业、经过充分研究的新闻通讯，结合来自多个来源的精选内容和原创分析与评论。它遵循 Morning Brew、The Hustle、TLDR 和 Benedict Evans 等出版物的现代新闻通讯最佳实践，产生信息丰富、引人入胜且可操作的内容。

输出是 Markdown 格式的完整、随时可发布的新闻通讯，适合电子邮件分发平台、网络发布或转换为 HTML。

## 核心能力

- 研究和策划来自多个网络来源的指定主题内容
- 生成主题聚焦或多主题新闻通讯，保持一致的语调
- 撰写引人注目的标题、摘要和原创评论
- 为最佳可读性和扫描优化内容结构
- 支持多种新闻通讯格式（每日摘要、周报、深度报道、行业简报）
- 包含相关链接、来源和归属
- 适应目标受众的语气和风格（技术、高管、通用）
- 生成具有一致品牌和结构的定期新闻通讯系列

## 何时使用此技能

**始终加载此技能当：**

- 用户请求生成新闻通讯、电子邮件摘要或内容精选
- 用户请求整理关于某个主题的新闻或动态摘要
- 用户想要创建定期新闻通讯格式
- 用户请求将某个领域的最新动态编译成简报
- 用户需要格式化的、适合电子邮件的多个精选项目内容
- 用户请求"周报"、"月度摘要"或"早间简报"

## 新闻通讯工作流程

### 第一阶段：规划

#### 步骤 1.1：理解新闻通讯需求

识别关键参数：

| 参数 | 描述 | 默认 |
|-----------|-------------|---------|
| **主题** | 要涵盖的主要主题领域 | 必填 |
| **格式** | 每日摘要、周报、深度报道或行业简报 | 周报 |
| **目标受众** | 技术、高管、通用或小众社区 | 通用 |
| **语气** | 专业、对话、机智或分析 | 对话-专业 |
| **长度** | 短（5分钟阅读）、中（10分钟）、长（15分钟+） | 中 |
| **章节** | 内容章节的数量和类型 | 4-6章节 |
| **频率上下文** | 一次性还是定期系列的一部分 | 一次性 |

#### 步骤 1.2：定义新闻通讯结构

根据格式选择适当的结构：

**每日摘要结构**：
```
1. 头条（1条，详细）
2. 快讯（3-5条，简短）
3. 一则数据/当日引言
4. 值得关注
```

**周报结构**：
```
1. 编者按/引言
2. 头条（2-3条，详细）
3. 趋势与分析（1-2条，原创评论）
4. 快讯（4-6条，简短摘要）
5. 工具与资源（2-3条）
6. 还有一件事/结语
```

**深度报道结构**：
```
1. 引言与背景
2. 背景/为什么重要
3. 关键发展（详细分析）
4. 专家观点
5. 下一步/影响
6. 延伸阅读
```

**行业简报结构**：
```
1. 执行摘要
2. 市场动态
3. 公司新闻与动向
4. 产品与技术更新
5. 法规与政策变化
6. 数据与指标
7. 展望
```

### 第二阶段：研究与策划

#### 步骤 2.1：多来源研究

使用网络搜索进行彻底研究。**新闻通讯的质量直接取决于研究的质量和时效性。**

**搜索策略**：

```
# 当前新闻和发展
"[主题] 新闻 [当前月] [当前年份]"
"[主题] 最新进展"
"[主题] 本周公告"

# 趋势和分析
"[主题] 趋势 [当前年份]"
"[主题] 分析专家观点"
"[主题] 行业报告"

# 数据和统计
"[主题] 统计 [当前年份]"
"[主题] 最新市场数据"
"[主题] 增长指标"

# 工具和资源
"[主题] 新工具 [当前年份]"
"[主题] 开源发布"
"[主题] 最佳资源 [当前年份]"
```

> **重要**：始终检查 `<current_date>` 以确保搜索查询使用正确的时间上下文。永远不要使用硬编码的年份。

#### 步骤 2.2：来源评估和选择

评估每个来源并策划最佳内容：

| 标准 | 优先级 |
|-----------|----------|
| **时效性** | 优先选择过去 7-30 天的内容 |
| **权威性** | 优先选择主要来源、官方公告、知名出版物 |
| **独特性** | 选择提供新视角或报道不足的故事 |
| **相关性** | 每个项目必须与新闻通讯声明的主题有明确联系 |
| **可操作性** | 优先选择读者可以采取行动的内容（工具、洞察、策略）|
| **多样性** | 新闻、分析、数据和实用资源的组合 |

#### 步骤 2.3：深度内容提取

对于关键故事，使用 `web_fetch` 阅读完整文章并提取：

1. **核心事实** — 发生了什么，谁参与，何时
2. **背景** — 为什么重要，背景信息
3. **数据点** — 具体数字、指标或统计
4. **引言** — 相关专家引言或官方声明
5. **影响** — 对读者的意义

### 第三阶段：写作

#### 步骤 3.1：新闻通讯头部

每个新闻通讯以一致的头部开始：

```markdown
# [新闻通讯名称]

*[标语或描述] — [日期]*

---

[可选：预览内部内容的一句话]
```

#### 步骤 3.2：章节写作指南

**头条/精选项目**：
- **标题**：引人注目、清晰、利益导向（不是标题党）
- **钩子**：让读者关心的开场句（1-2句）
- **正文**：关键事实和背景（2-4段）
- **重要性**：与读者世界的联系（1段）
- **来源链接**：始终归因并链接到原始来源

**快讯/简短项目**：
- **格式**：粗体标题 + 2-3 句摘要 + 来源链接
- **焦点**：每个项目一个关键要点
- **效率**：读者无需点击即可获得基本洞察

**分析/评论章节**：
- **语调**：新闻通讯对趋势或发展的独特视角
- **结构**：观察 → 背景 → 影响 →（可选）可操作要点
- **证据**：每个声明都有数据或来源信息支持

#### 步骤 3.3：写作标准

| 原则 | 实现 |
|-----------|---------------|
| **可扫描** | 使用标题、粗体文本、项目符号和短段落 |
| **引人入胜** | 以最有趣的视角开头，而非时间顺序 |
| **简洁** | 每个句子都值得保留 — 坚决削减填充词 |
| **准确** | 每个事实都有来源，每个数字都经过验证 |
| **归因** | 始终使用内联链接归功于原始来源 |
| **人性化** | 像知识渊博的朋友一样写作，而非新闻稿 |

**按受众的语气校准**：

| 受众 | 语气 | 示例 |
|----------|------|---------|
| **技术** | 精确、不解释术语、假定专业知识 | "新 API 支持通过流控制窗口进行背压处理的 gRPC 流式传输。" |
| **高管** | 影响导向、底线、战略 | "此次收购使公司 X 在企业细分市场份额达到 40%，直接威胁现有者 Y 的定价权。" |
| **通用** | 易懂、使用类比、解释概念 | "把它想象成数据的通用翻译器 — 它让任何应用无需学习新语言就能与任何数据库对话。" |

### 第四阶段：组装与完善

#### 步骤 4.1：组装新闻通讯

按照选择的结构模板将所有章节组合成最终文档。

#### 步骤 4.2：页脚

每个新闻通讯以：

```markdown
---

*[新闻通讯名称] 是 [描述其是什么]。*
*[如何订阅/分享/反馈]*

*来源：所有链接都以内联方式提供。此新闻通讯策划和总结具有原创评论的公开信息。*
```

#### 步骤 4.3：质量检查清单

最终确定之前，验证：

- [ ] **每个事实声明都有来源链接** — 无未注明来源的断言
- [ ] **所有链接都有效** — 验证的 URL 来自搜索结果
- [ ] **日期引用使用实际当前日期** — 无硬编码或假设日期
- [ ] **内容是当前的** — 所有主要项目都在预期范围内
- [ ] **无重复故事** — 每个项目只出现一次
- [ ] **格式一致** — 标题、项目符号、链接在整篇中使用相同风格
- [ ] **覆盖平衡** — 不被单一来源或视角主导
- [ ] **长度适当** — 符合指定的长度目标
- [ ] **开场引人** — 前 2 句话让读者想继续
- [ ] **结尾清晰** — 新闻通讯以令人难忘或可操作的内容结束
- [ ] **已校对** — 无拼写错误、格式损坏或不完整句子

## 适配示例

### 科技新闻通讯
- 表情符号使用：✅ 适度（章节标题）
- 章节：头条、深度报道、快讯、开源聚焦、开发者工具
- 语气：技术-对话

### 商业/金融新闻通讯
- 表情符号使用：❌ 极少到无
- 章节：市场概览、交易流、公司新闻、数据角、展望
- 语气：专业-分析

### 行业特定新闻通讯
- 表情符号使用：适度
- 章节：法规更新、市场数据、创新观察、人事变动、活动
- 语气：专家-权威

### 创意/营销新闻通讯
- 表情符号使用：✅ 自由
- 章节：活动聚焦、趋势观察、本周病毒、我们喜欢的工具、灵感
- 语气：热情-专业

## 输出处理

生成后：

- 将新闻通讯保存到 `/mnt/user-data/outputs/newsletter-{topic}-{date}.md`
- 使用 `present_files` 工具向用户展示新闻通讯
- 提供调整章节、语气、长度或重点领域的选项
- 如果用户想要 HTML 输出，注明 Markdown 可以使用标准工具转换

## 注意事项

- 此技能与 `deep-research` 技能结合使用效果最佳，可实现全面主题覆盖 — 加载两者以获得需要深度分析的通讯
- 始终使用 `<current_date>` 进行搜索和日期引用中的时间上下文
- 对于定期新闻通讯，建议保持一致的结构以便读者形成期望
- 策划时，质量胜于数量 — 5 个优质项目胜过 15 个平庸项目
- 正确归因所有内容 — 新闻通讯通过透明来源建立信任
- 避免总结读者无法访问的付费内容
- 如果用户提供要包含的特定 URL 或文章，将其与你的精选发现一起整合
- 新闻通讯应该在摘要中提供足够价值，即使读者不点击每个链接也能受益
