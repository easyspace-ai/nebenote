# 学术论文评审技能

## 概述

本技能对学术论文和研究出版物进行结构化的同行评审质量分析。遵循顶级会议（NeurIPS、ICML、ACL、Nature、IEEE）使用的学术评审标准，提供严谨、建设性和平衡的评估。

评审涵盖**摘要、优势、方法论评估、贡献评估、文献定位和可操作建议**——所有内容均基于论文本身的证据。

## 核心能力

- 解析并理解上传的PDF或获取的URL中的学术论文
- 按照顶级会议评审模板生成结构化评审
- 评估方法论严谨性（实验设计、统计有效性、可复现性）
- 评估贡献的创新性和重要性
- 通过有针对性的文献检索在更广泛的研究领域中定位工作
- 识别局限性、差距和潜在改进
- 生成详细评审和简明执行摘要两种格式
- 支持任何科学领域（计算机、生物、物理、社会科学等）的论文

## 何时使用此技能

**始终加载此技能当：**

- 用户提供论文URL（arXiv、DOI、会议论文集、期刊链接）
- 用户上传研究论文或预印本的PDF
- 用户要求"审查"、"分析"、"批评"、"评估"或"总结"研究论文
- 用户想了解研究的优势和劣势
- 用户请求对学术工作进行同行评审风格的评估
- 用户请求帮助准备会议或期刊投稿的评审

## 评审方法论

### 第一阶段：论文理解

在形成任何判断之前，仔细阅读并理解论文。

#### 步骤 1.1：识别论文元数据

提取并记录：

| 字段 | 描述 |
|-------|-------------|
| **标题** | 完整论文标题 |
| **作者** | 作者列表及所属机构 |
| **发表场所/状态** | 发表场所、预印本服务器或投稿状态 |
| **年份** | 发表或投稿年份 |
| **领域** | 研究领域和子领域 |
| **论文类型** | 实证、理论、综述、立场论文、系统论文等 |

#### 步骤 1.2：深度阅读

系统阅读论文：

1. **摘要与引言** — 识别声称的贡献和动机
2. **相关工作** — 注意作者如何相对于先前技术定位自己的工作
3. **方法论** — 详细理解提出的方法、模型或框架
4. **实验/结果** — 检查数据集、基线、指标和报告的结果
5. **讨论与局限性** — 注意任何自我识别的局限性
6. **结论** — 将结论性声明与实际呈现的证据进行比较

#### 步骤 1.3：关键声明提取

明确列出论文的主要声明：

```
声明 1：[关于贡献或发现的具体声明]
证据：[论文中支持此声明的证据]
强度：[强/中/弱]

声明 2：[...]
...
```

### 第二阶段：批判性分析

#### 步骤 2.1：文献背景检索

使用网络搜索了解研究领域：

```
搜索查询：
- "[论文主题] 当前最先进水平 [当前年份]"
- "[关键方法名称] 比较基准"
- "[作者] 之前的工作 [主题]"
- "[具体技术] 局限性批评"
- "综述 [研究领域] 最新进展"
```

对关键相关论文或综述使用 `web_fetch` 以了解这项工作在整体中的位置。

#### 步骤 2.2：方法论评估

使用以下框架评估方法论：

| 标准 | 要问的问题 | 评分 |
|-------|-----------------|--------|
| **合理性** | 方法在技术上是正确的吗？有没有逻辑漏洞？ | 1-5 |
| **创新性** | 真正新的东西是什么 vs. 增量改进？ | 1-5 |
| **可复现性** | 细节是否足以复现？代码/数据可用吗？ | 1-5 |
| **实验设计** | 基线是否公平？消融实验是否充分？数据集是否合适？ | 1-5 |
| **统计严谨性** | 结果是否具有统计显著性？报告了误差线了吗？多次运行了吗？ | 1-5 |
| **可扩展性** | 方法是否可扩展？讨论了计算成本吗？ | 1-5 |

#### 步骤 2.3：贡献重要性评估

评估重要性级别：

| 级别 | 描述 | 标准 |
|-------|-------------|----------|
| **里程碑** | 从根本上改变领域 | 新范式，广泛适用的突破 |
| **重要** | 推动最先进水平的强贡献 | 有扎实证据的明确改进 |
| **中等** | 有一些局限性的有用贡献 | 增量但有效的改进 |
| **边缘** | 相比现有工作的最小进展 | 小收益，狭窄适用性 |
| **低于阈值** | 不符合发表标准 | 根本性缺陷，证据不足 |

#### 步骤 2.4：优势与劣势分析

对于每个优势或劣势，提供：
- **内容**：具体观察
- **位置**：章节/图/表参考
- **重要性**：对论文声明或实用性的影响

### 第三阶段：评审综合

#### 步骤 3.1：组装结构化评审

使用以下模板生成最终评审。

## 评审输出模板

```markdown
# 论文评审：[论文标题]

## 论文元数据
- **作者**：[作者列表]
- **场所**：[发表场所或预印本服务器]
- **年份**：[年份]
- **领域**：[研究领域]
- **论文类型**：[实证/理论/综述/系统/立场]

## 执行摘要

[2-3段论文核心贡献、方法和主要发现的摘要。
首先说明您的整体评估：论文做得好的地方、不足之处，
以及贡献是否足以达到声称的场所/影响级别。]

## 贡献摘要

1. [第一个声称的贡献 — 一句话]
2. [第二个声称的贡献 — 一句话]
3. [如有其他贡献]

## 优势

### S1：[简洁的优势标题]
[详细解释，并具体引用论文中的章节、图表或表格。
解释这为什么是一个优势及其重要性。]

### S2：[简洁的优势标题]
[...]

### S3：[简洁的优势标题]
[...]

## 劣势

### W1：[简洁的劣势标题]
[详细解释并具体引用。解释这个劣势对论文声明的影响。
建议如何解决。]

### W2：[简洁的劣势标题]
[...]

### W3：[简洁的劣势标题]
[...]

## 方法论评估

| 标准 | 评分 (1-5) | 评估 |
|-------|:---:|------------|
| 合理性 | X | [简要理由] |
| 创新性 | X | [简要理由] |
| 可复现性 | X | [简要理由] |
| 实验设计 | X | [简要理由] |
| 统计严谨性 | X | [简要理由] |
| 可扩展性 | X | [简要理由] |

## 给作者的问题

1. [能澄清疑虑或歧义的具体问题]
2. [关于方法选择或替代方法的问题]
3. [关于可推广性或实际适用性的问题]

## 次要问题

- [拼写错误、格式问题、图表不清晰、符号不一致]
- [应该引用但缺失的参考文献]
- [改进清晰度的建议]

## 文献定位

[这项工作与当前最先进水平有什么关系？
是否引用了关键的相关工作？比较是否公平和全面？
缺少哪些重要的相关工作？]

## 建议

**整体评估**：[接受/弱接受/边界/弱拒绝/拒绝]

**置信度**：[高/中/低] — [置信度级别的理由]

**贡献级别**：[里程碑/重要/中等/边缘/低于阈值]

### 可操作的改进建议
1. [具体的、建设性的建议]
2. [具体的、建设性的建议]
3. [具体的、建设性的建议]
```

## 评审原则

### 建设性批评
- **始终建议如何修复** — 不要只是指出问题；要提出解决方案
- **给予应有的信任** — 即使是有缺陷的论文也要承认真正的贡献
- **要具体** — 引用具体的章节、公式、图表和表格
- **区分次要和主要** — 区分致命缺陷和可修复的问题

### 客观性标准
- ❌ "这篇论文写得不好"（模糊、无帮助）
- ✅ "第3.2节在未提供形式定义的情况下引入了符号X，使得定理1的证明难以理解。建议在问题公式化之后添加符号表。"（具体、可操作）

### 伦理评审实践
- 不要基于作者声誉或机构而否定工作
- 根据其自身优点评估工作
- 建设性地标记潜在的伦理问题（数据集中的偏见、双重使用的影响）
- 保密未发表的工作

## 按论文类型的适配

| 论文类型 | 重点领域 |
|------------|-------------|
| **实证** | 实验设计、基线、统计显著性、消融实验、可复现性 |
| **理论** | 证明正确性、假设合理性、边界紧度、与实践的联系 |
| **综述** | 全面性、分类质量、最新工作覆盖、综合见解 |
| **系统** | 架构决策、可扩展性证据、实际部署、工程贡献 |
| **立场** | 论点连贯性、声明证据、影响潜力、描述公平性 |

## 要避免的常见陷阱

- ❌ 评审你希望写的论文，而不是提交的论文
- ❌ 要求范围不合理的多余实验
- ❌ 因未解决不同问题而惩罚论文
- ❌ 过度受写作质量影响而非技术贡献
- ❌ 将未与自己的工作进行比较视为劣势
- ❌ 只提供摘要而没有批判性分析

## 质量检查清单

在最终确定评审之前，验证：

- [ ] 论文已完整阅读（不只是摘要和引言）
- [ ] 所有主要声明都已识别并针对证据进行评估
- [ ] 至少提供3个优势和3个劣势，并附具体引用
- [ ] 方法论评估表格完整，包含评分和理由
- [ ] 给作者的问题针对真正的歧义，而非修辞性批评
- [ ] 进行了文献检索以将贡献置于背景中
- [ ] 建议是可操作和建设性的
- [ ] 整体评估与已识别的优势和劣势一致
- [ ] 评审语气专业且尊重
- [ ] 次要问题与主要关切分开

## 输出格式

- 以 **Markdown** 格式输出完整评审
- 在沙箱中工作时，将评审保存到 `/mnt/user-data/outputs/review-{paper-topic}.md`
- 使用 `present_files` 工具向用户展示评审

## 注意事项

- 此技能补充 `deep-research` 技能 — 当用户希望在更广泛领域的背景下评审论文时，同时加载两者
- 对于付费论文，使用可访问的内容（摘要、公开可用版本、预印本镜像）
- 根据用户需求调整评审深度：快速分类的简要评估 vs. 提交准备的全面的评审
- 当比较评审多篇论文时，在所有评审中保持一致的标准
- 始终披露评审的局限性（例如，"我无法详细验证附录B中的证明"）
