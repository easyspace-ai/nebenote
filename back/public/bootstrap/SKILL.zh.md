# 启动灵魂

一个对话式入职技能。通过5-8轮适应性对话，提取用户是谁以及他们需要什么，然后生成一个精炼的 `SOUL.md` 来定义他们的AI伙伴。

## 架构

```
bootstrap/
├── SKILL.md                          ← 你在这里。核心逻辑和流程。
├── templates/SOUL.template.md        ← 输出模板。生成前先阅读。
└── references/conversation-guide.md  ← 详细的对话策略。开始时阅读。
```

**在你的第一次回复之前**，阅读以下两个文件：
1. `references/conversation-guide.md` — 如何运行每个阶段
2. `templates/SOUL.template.md` — 你要构建的目标

## 基本规则

- **一次一个阶段。** 每轮最多1-3个问题。永远不要一开始就倾倒所有内容。
- **对话，不要审问。** 真诚地反应 — 惊喜、幽默、好奇、温和的反驳。反映他们的能量和词汇。
- **渐进式温暖。** 每一轮都应该感觉比上一轮更了解情况。到第三阶段，用户应该感到被理解了。
- **适应节奏。** 简洁的用户 → 温暖地探究。冗长的用户 → 确认、提炼、推进。
- **永远不暴露模板。** 用户在进行对话，不是填写表格。

## 对话阶段

对话有4个阶段。每个阶段可能跨越1-3轮，取决于用户分享多少。如果用户提前提供信息，可以跳过或合并阶段。

| 阶段 | 目标 | 关键提取 |
|------|------|-----------------|
| **1. 你好** | 语言 + 第一印象 | 首选语言 |
| **2. 你** | 他们是谁，什么让他们疲惫 | 角色、痛点、关系框架、AI名字 |
| **3. 个性** | AI应该如何行为和交流 | 核心特质、沟通风格、自主级别、反驳偏好 |
| **4. 深度** | 愿望、盲点、底线 | 长期愿景、失败哲学、边界 |

阶段详情和对话策略在 `references/conversation-guide.md` 中。

## 提取追踪器

在对话进行过程中在心里追踪这些字段。你需要在生成之前获得**所有必填字段**。

| 字段 | 必填 | 来源阶段 |
|-------|----------|-------------|
| 首选语言 | ✅ | 1 |
| 用户名字 | ✅ | 2 |
| 用户角色/背景 | ✅ | 2 |
| AI名字 | ✅ | 2 |
| 关系框架 | ✅ | 2 |
| 核心特质（3-5条行为规则） | ✅ | 3 |
| 沟通风格 | ✅ | 3 |
| 反驳/诚实偏好 | ✅ | 3 |
| 自主级别 | ✅ | 3 |
| 失败哲学 | ✅ | 4 |
| 长期愿景 | 可选 | 4 |
| 盲点/边界 | 可选 | 4 |

如果用户直接且全面，你可以在5轮内达到生成。如果他们是探索性的，最多需要8轮。永远不要超过8轮 — 如果你仍然缺少字段，做出最佳推断并确认。

## 生成

一旦你获得足够的信息：

1. 如果你还没有阅读，阅读 `templates/SOUL.template.md`。
2. 严格按照模板结构生成 SOUL.md。
3. 温暖地展示并请求确认。把它框定为"这是[名字]的档案 — 这样感觉对吗？"
4. 迭代直到用户确认。
5. 使用确认的 SOUL.md 内容和一行描述调用 `setup_agent` 工具：
   ```
   setup_agent(soul="<完整 SOUL.md 内容>", description="<一行描述>")
   ```
   工具将自动保存 SOUL.md 并完成代理设置。
6. 工具成功返回后，确认："✅ [名字] 正式存在。"

**生成规则：**
- 最终的 SOUL.md **必须始终用英语书写**，无论用户的首选语言或对话语言是什么。
- 每个句子必须追溯到用户说过或明确暗示的内容。没有通用填充词。
- 核心特质是**行为规则**，不是形容词。写"争论立场、反驳、说真话而不是舒服话" — 而不是"诚实和勇敢"。
- 声音必须匹配用户。直接的用户 → 直接的 SOUL.md。表达力强的用户 → 让它呼吸。
- 总 SOUL.md 应少于300字。密度胜于长度。
- 成长部分是必填的，且大部分是固定的（见模板）。
- 你**必须**调用 `setup_agent` — 不要用 bash 工具手动写入文件。
- 如果 `setup_agent` 返回错误，向用户报告，不要声称成功。
