第 1 章：不是又一个 LLM 包装器

核心定位：

pi 是一个 agent 运行时，不是一个调用库

关键差异：

  • LangChain：开发者定义的链式编排
  • Vercel AI SDK：统一流式调用层
  • CrewAI：多 agent 团队协作
  • pi：LLM 驱动的循环引擎

得到了什么

更灵活的任务执行，LLM 自主决定工具调用

放弃了什么

失去了显式控制流的可预测性

第 2 章：七个包不是七个项目

核心架构：洋葱分层

  • L1: pi-ai — 统一 LLM 调用层
  • L2: pi-agent-core — 循环引擎
  • L3: pi-coding-agent — 产品内核
  • L4: 产品壳（CLI、Slack Bot、Web UI）

Lockstep 版本策略

所有 7 个包始终使用同一个版本号

得到了什么

强制分层纪律，独立测试，渐进式采用

放弃了什么

开发环境复杂度，单个 bug 修复需升级全部包

第 8 章：agentLoop — 发动机只管转

核心设计：无状态循环引擎

agentLoop 本身是无状态的，不持有任何跨次调用的状态

循环逻辑：

  1. 调用 LLM → 获取响应
  2. 检查是否有工具调用
  3. 并行/串行执行工具
  4. 将结果加入消息列表 → 再次调用 LLM
  5. 直到 LLM 决定停止或收到外部终止信号

得到了什么

极致的复用性，可测试性，控制灵活性

放弃了什么

上层需要管理状态，增加了使用复杂度

第 14 章：System Prompt 是一套装配流程

核心思想：

System Prompt 不是静态字符串，而是运行时动态组装的产物

装配来源：

  • 基础模板（内置系统提示）
  • AGENTS.md 文件（项目特定配置）
  • 用户自定义配置
  • Extension 注入的内容

得到了什么

高度定制化，动态适应不同场景

放弃了什么

增加了复杂度，调试难度提高

第 15 章：Extension 系统 — 让产品长出新器官

核心能力：

Extension 是 TypeScript 代码模块，可注册新工具、命令、事件处理器和 UI 扩展

设计原则：

  • 显式注册：所有扩展必须显式注册
  • 隔离运行：每个 Extension 有独立的上下文
  • 生命周期管理：支持加载、卸载、更新

得到了什么

无限扩展性，产品功能可动态增长

放弃了什么

增加了系统复杂度，安全风险提高

第 30 章：极简核心，能力外置

核心哲学：

核心代码保持极简，所有非核心能力外置

实践体现：

  • agentLoop 只有 ~1,900 行代码
  • 130+ 工具全部外置实现
  • Skill 机制用文档替代代码逻辑

得到了什么

核心稳定，扩展灵活，维护成本低

放弃了什么

核心功能有限，依赖生态系统

总结：pi 架构的核心决策

设计哲学

  • 极简核心，能力外置
  • 循环引擎无状态，上层管理状态
  • 显式注册优于隐式发现
  • 文档驱动优于代码驱动

架构优势

  • 高度可扩展，支持动态功能增长
  • 核心稳定，易于测试和维护
  • 灵活适配不同使用场景
